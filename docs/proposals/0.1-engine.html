Why

The studio has shipped three original web games from scratch. Each one re-solved the same nine problems, and every solution diverged. The iOS port of Crownfall then rewrote the rules a second time in Swift. A fourth game on this path costs the same as the first three did.

The bloom in both games is the tell. Each blurs a copy of the frame with a Canvas filter and composites it back with lighter or screen. It looks right on a laptop and is the first thing that will fall over on a phone. A shader does the same job in a fraction of the time, but only once someone owns a renderer to put it in.

The rules code is already in good shape for this. All three games keep their logic DOM-free and deterministic behind a seeded RNG, with tests that run headless. The engine takes everything around that logic and leaves the logic alone.

Scope

0.1 is

  • A runtime library, @kiln/engine, with subpath modules
  • A CLI: dev, build, export web, atlas, test
  • A WebGL2 renderer with a Canvas 2D fallback behind one interface
  • A post-effect chain: bloom, vignette, grade, tint, shake
  • A scene tree with sprites, tile layers, camera, particles and canvas-drawn UI
  • Procedural painting, atlas packing and PNG export
  • A WebAudio synth for music moods and sound effects
  • An input action map for mouse, touch and keyboard
  • Versioned saves with migrations
  • A headless test kit, a sample project and generated API docs

0.1 is not

  • An editor or inspector GUI
  • 3D in any form
  • iOS, Android or desktop export. Those are 0.2 and 0.3
  • A physics engine. Rect and circle overlap plus grid helpers only
  • Networking
  • A scripting language. TypeScript is the scripting language
  • An asset pipeline beyond loading PNG and JSON
  • WebGPU

Assumed decision. This proposal takes the in-house engine as decided. The cost it carries, engine days that are not game days, is tracked below as a risk with a cap, not reopened here.

Architecture

Godot's shape, cut down to the size of these games. A tree of nodes, a renderer behind an interface, and the parts every game needs pulled into named modules. Games sit on top and own their rules, data and scenes.

Two rules keep it honest. Nothing below scene may import the DOM, so the whole lower half runs under bun test. And the renderer is only ever touched through its interface, so the WebGL2 and Canvas 2D backends are interchangeable and a native backend has a place to land later without a rewrite.

What the other two games bring

  • Emberwake supplies the fixed-step loop, the pointer-to-logical mapping in its input manager, save validation, and the atmosphere and cast-shadow drawing. It also tests that the scene API works for a real-time action game, not just a turn-based one.
  • Breach Protocol supplies grid helpers such as reachable tiles and pathfinding for core.grid. Line of sight and cover are rules and stay in the game. Its DOM interface stays as it is in 0.1. It adopts core, audio, save and the CLI, which still removes three duplicated modules.

API sketch

What a game looks like on the engine. Enough to check the shape feels right before any of it exists.

// kiln.json
{
  "name": "crownfall",
  "entry": "src/main.ts",
  "viewport": { "width": 1280, "height": 800, "scale": "fit" },
  "renderer": "webgl2", "fallback": "canvas2d",
  "post": ["bloom", "vignette", "dayTint"]
}
// src/art/creatures.ts — same painter primitives, now registered by name
import { defineSprite, ball, slab, limb, ramp } from "@kiln/engine/art";

export const knight = defineSprite("knight", { w: 48, h: 48, mirror: true }, (p) => {
  const steel = ramp("#8a93a8"), cloak = ramp("#7a2f3a");
  slab(p, 14, 24, 20, 18, cloak);
  ball(p, 24, 14, 9, 9, steel);
  limb(p, 20, 30, 8, 44, 4, steel);
});
// src/scenes/adventure.ts — rules untouched, drawing becomes nodes
import { Scene, Sprite, TileLayer, Camera2D, CanvasLayer } from "@kiln/engine/scene";
import { Panel, Button } from "@kiln/engine/scene/ui";

export class Adventure extends Scene {
  camera = this.add(new Camera2D({ bounds: map.pixelRect }));
  terrain = this.add(new TileLayer(map, terrainVariant));
  hud = this.add(new CanvasLayer());

  ready() {
    for (const hero of state.heroes) this.add(new Sprite(hero.sprite, hero.pos));
    this.hud.add(new Button("End turn", { at: [1180, 760], action: "endTurn" }));
  }
  update(dt: number) { tickAnimations(state, dt); }
  onAction(name: string) { if (name === "endTurn") endTurn(state); }
}
// src/main.ts
import { App } from "@kiln/engine/app";

const app = await App.create({ canvas: "#game" });
app.input.map({ endTurn: ["KeyE", "Enter"], nextHero: ["KeyH"], menu: ["Escape"] });
app.scenes.change(new Title());

Three things to notice. Painters are plain functions the atlas calls once at boot, exactly as today. A scene owns nodes but the game state stays a plain serializable object, so saves and tests don't change. And input is named actions, so the same scene works untouched when 0.2 adds touch and a gamepad.

Definition of done

  • Crownfall and Emberwake contain no rendering, audio, input, save, loop or server code of their own.
  • Breach Protocol uses the engine's core, audio, save and CLI.
  • Every screenshot in each game's screenshots/ folder matches the new build within a small pixel tolerance, on both backends.
  • All ten existing test files pass unchanged, alongside the engine's own suite.
  • Version 1 saves from both games still load.
  • The iOS sprite export is kiln atlas, not a console snippet.
  • A new game starts from the sample project with one command.
  • The renderer backend contract is written down, so a third backend can be built from the document alone.

For comparison, Godot's web export downloads tens of megabytes before the first frame. Staying two orders of magnitude under that is the reason to own this layer rather than adopt it.

Decisions

Each needs a yes before M0. A recommendation is given for all of them.

Language

TypeScript, strict, for the engine

Games may stay JavaScript and get types from the shipped declarations. Migrate game files to TypeScript as they are touched, not as a project.

AlternativeKeep the engine in JavaScript with JSDoc. Cheaper today, and every consumer pays for it later.
Renderer

WebGL2 first, Canvas 2D fallback

Both behind one interface. WebGL2 is what makes bloom cheap and mobile viable. Canvas 2D covers old hardware and lets the interface land before the shaders do.

AlternativeWebGPU. Not in 0.1. Safari coverage is uneven and batched 2D sprites gain nothing from it.
Object model

Scene tree, not ECS

Matches how all three games are already written, as screens with update and draw. An entity-component system adds ceremony without a performance need at this scale.

AlternativeECS. Revisit only if a game needs thousands of live entities.
UI

Canvas-drawn in 0.1

Crownfall's panels, buttons and tooltips become nodes. That covers two of three games. A DOM overlay layer for menu-heavy games like Breach Protocol is 0.2 work.

AlternativeDOM UI from day one. Splits the renderer across two systems before either is stable.
Repository

Its own repo at games/engine

Same convention as every other subrepo in the workspace. Games depend on it with a link during 0.x. Publish to npm only when a game outside the folder needs it.

AlternativeA folder inside Crownfall. Faster for a week, then the extraction has to happen anyway.
The Swift port

Freeze it

0.2 puts the engine on iOS and Android through a WebView shell with the frame-time budget above as the gate. A native renderer backend is the fallback if the gate fails, not the plan.

AlternativeKeep maintaining the port. Every rules change is then made twice, per game.

The name is the seventh decision. Kiln is a placeholder chosen because the art is fired in code at boot. It goes into the package scope and the CLI, so it should be settled before M0.

After 0.1

  • 0.2 Mobile. Capacitor shells for iOS and Android, touch gestures, safe areas, prebaked atlas, IndexedDB saves, the DOM overlay layer, and the frame-time gate on a real device.
  • 0.3 Desktop. A Tauri shell, gamepad support, fullscreen, and a build that can go to Steam.
  • 0.4 Tooling. A scene inspector overlay, hot reload for painters, and input record-and-replay for tests.
  • Not planned. 3D, an editor GUI, a scripting language. Each would be its own proposal with a game that needs it.

Next step. Settle the name and the renderer decision. M0 then starts by lifting the loop and Canvas 2D drawing out of Crownfall into a new repo, and the sample project is running the same day.
