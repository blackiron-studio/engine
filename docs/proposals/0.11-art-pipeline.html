The art pipeline: generic import, animation and rigs

Godot and Unity do not make art. They give an artist a good import path and good ways to animate what comes in, and they stay out of the way of the style. Kiln has to do the same, with one difference: our artist is an image model, and our authoring tool is a command line, because there is no editor and the games are generated. This proposal makes that first-class and keeps every part of it generic. Nothing in it knows what a warden or a knight is.

Principles

  • Data, not code, describes art. A sprite set is a PNG plus a manifest. A rig is a manifest. A game names them; it never paints them in scene code.
  • The engine has no opinion about the style beyond enforcing the one the project declares. The style bible is the project's, the palette snap is the mechanism.
  • Every step is a command with a report and a preview, because there is no editor to look at. The harness renders what came in.
  • Generic means every host. Whatever the importer writes bakes into the atlas for web, iOS, Android and the desktops alike. This landed with the knight and stays the rule.
  • No skinning, no 3D. Cutout rigs cover what 2D games need. Mesh deformation is a later proposal if a game asks.

1. Sprite sets

Today an import yields frames and flat animation tags. A sprite set is the same PNG with a richer manifest, written by the importer and read by one call.

assets/knight.json
{
  "frames": [ ... ],                          // as now: x, y, w, h, duration
  "meta": { "image": "knight.png", "pitch": 4, "height": 66,
    "anchor": [0.5, 0.97],
    "animations": {
      "walk": { "fps": 7, "loop": true,
        "facings": { "down": [4, 5], "up": [1], "left": [2, 6], "right": [3, 7] },
        "events": { "1": "step", "3": "step" } },
      "attack": { "fps": 10, "loop": false, "facings": { "right": [8, 9] }, "mirror": true,
        "events": { "1": "hit" } },
      "hurt": { "frames": [13], "hold": 0.5 }
    },
    "hitboxes": { "8": { "x": 20, "y": 10, "w": 30, "h": 40 } }
  }
}
  • defineSpriteSet("knight", "assets/knight.json") registers frames and every animation as knight.walk and so on, exactly like defineSheet does now.
  • AnimatedSprite.facing is an angle or one of four names. play("walk") picks the facing's frames and flips when mirror says a left set is the right set flipped. Games stop writing knight.left and knight.right by hand.
  • onEvent("step" | "hit", frame) fires from the frame table, so footsteps and hit frames live in data.
  • Hitboxes per frame feed the physics or the game's own checks; the sim never guesses where the sword is.
  • The importer's flags become manifest fields: --anim walk=down:4,5;up:1;left:2,6;right:3,7, and a --manifest that takes the whole thing from a file so a generator's brief and the import agree.

2. Rigs

Generators give poses. Games want cycles. A cutout rig turns one drawn character into every cycle a game needs, the way Godot's Skeleton2D and Unity's 2D Animation do, without an editor: the parts come from a sheet, the bones from a template, the motion from a library.

  • Parts are frames of a sprite set named by role: head, torso, arm.l, weapon. The importer gets a --parts mode: a sheet of parts on a flat ground, found and named by a legend in the manifest. A generator produces such a sheet from a brief the engine prints.
  • Bones form a hierarchy with pivots in part space. Templates ship with the engine: humanoid, quadruped, flyer, blob. A rig manifest names a template and the parts, and overrides pivots when the drawing needs it.
  • Clips come two ways. Procedural clips are functions of time and a few parameters (stride, bounce, weapon length) that pose the template's bones: idle breathing, walk and run, a swing, a thrust, a hurt recoil, a fall, a cast, a carry. They give every rigged character motion on day one. Keyframed clips are JSON tracks, for the moments a game wants exact.
  • Rig2D is a node: play(clip), blend, layer("upper", clip) so the legs walk while the arms swing, facing picks the draw order and mirrors. Frame events and hitboxes work the same as on sprite sets; hitboxes attach to bones.
  • The kernel later. A rig is a dozen transforms per character. Posing stays in script first; when a game rigs hundreds of enemies, posing moves behind a RIG op on the node table, the way pools did.

3. Tiles and environments

  • kiln art import --tiles 32: a generated tileset on a flat ground is keyed, pitched and cut on the tile grid; each tile's four edges are compared with its neighbours to derive the autotile mask it plays, and seams that do not close are reported with the tile number.
  • Terrain sets like Godot's: a manifest lists terrains (grass, path, water) and which tiles carry which edges; TileMap paints from terrain ids and picks tiles by mask, as it does for painted autotiles now.
  • Decoration and prop sheets import as sprite sets with an anchor at the feet and a sort key, so a tree stands on the ground and sorts with characters.

4. The style bible and its linter

The style bible grows two fields, pitch and castHeight, and gets a command. kiln art check reads every sheet under assets/ and every painted sprite and reports what breaks the bible: a pitch off by more than one, a character taller than the cast by a fifth, colours farther from the palette than a threshold before snapping, an outline missing where the bible asks for one. The check runs in kiln verify, so a sheet that would look wrong fails the build before anyone sees it.

5. Briefs: the engine tells the generator what to draw

Godot's artist knows the rules from experience. Ours needs them written down every time. kiln art brief character --facings 4 --clips walk,attack,hurt prints the prompt that produces a sheet the importer likes: a flat magenta ground, a strict grid with a stated cell, one pose per cell in a stated order, the pitch and height from the style bible, the palette as hex, no anti-aliasing, no drop shadow. kiln art brief parts prints the parts-sheet brief for a rig, --tiles the tileset brief. A game's generation step becomes: ask for the brief, hand it to the model, import the result, run the check.

6. Review and round trip

  • kiln art strip renders every animation of every set and rig as a strip PNG, one row per animation, one column per frame or per sampled time; kiln verify keeps them as goldens like scene snapshots, so a regenerated sheet that changes a walk fails visibly.
  • kiln art export --aseprite writes any set back out as PNG plus Aseprite JSON with tags, so a person can fix a hand or a face and re-import without touching the game.
