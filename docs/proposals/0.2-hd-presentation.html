Why it looks low-res

Nothing in 0.1 is blurry. It is small. Three numbers stack up, and each one alone would be fine.

NumberTodayWhat a 2560-wide display shows
Design resolution320×180 in the starters, 640×360 in the demoEvery game unit is 8 screen pixels wide in a starter, 4 in the demo
Art density16 px tiles, a 16×24 heroA tile is a 128 px square of 256 art pixels. The eye reads the grid, not the drawing
Render targetRendered at design size, then upscaled with nearest filteringParticles, bloom, text and camera motion are all quantised to that same 8 px grid. Bloom is computed at 80×45
TextA 5×7 bitmap font drawn as spritesHUD letters are 40 px tall with 7 rows of detail

The 0.1 choices were right for proving the engine, and the crisp look is worth keeping. The fix is not to blur anything. It is to turn three dials that 0.1 left at their minimum.

The three dials

  • Design resolution, the coordinate space games are written in. Move the default from 320×180 to 1280×720. Four times the canvas, same aspect.
  • Art density, how many art pixels a subject gets. Move tiles from 16 to 32 px, characters from 16×24 to 32×48, trees from 32×48 to 64×96. Same footprint on screen, four times the detail.
  • Render scale, the resolution the frame is composed at. Move from "design size" to "native": the offscreen target matches the canvas backing store, so sub-pixel camera motion, particles, glow and text are smooth while sprites stay pixel-exact.

Scope

0.2 is

  • Native-resolution rendering with a sub-pixel camera and a bloom mip chain
  • Painter 2.0: materials, textures, wider ramps, selective outlines, masks and palette swaps
  • The demo and the three game starters re-authored at 32 px on 1280×720
  • HD text from any web font, plus UI anchors, containers and 9-slice panels
  • A lighting pass: ambient darkness and point lights that actually light the ground
  • Imported PNG sprite sheets and audio samples alongside painted art and synth sound
  • A TileMap node with autotiling, animated tiles and built-in collision
  • Parallax layers, overlay scenes, gamepad and touch controls
  • LUT colour grading, grain and scanline toggles, a screenshot command

0.2 is not

  • Mobile or desktop shells. Those are 0.3, and they benefit from 0.2 landing first
  • Normal-mapped lighting or shadow casting
  • An editor, 3D, networking, physics beyond tiles and overlap
  • WebGPU
  • Feature parity for the Canvas 2D backend, which becomes a compatibility fallback

Retro stays possible. Integer scaling, the 5×7 font and 16 px art remain supported and one config switch away. 0.2 changes the defaults new projects start from, not what the engine can do.

Pipeline

The frame in 0.2, in order. Passes marked on the left are new; the rest exist and change size.

Scenechanged
One sprite batch into an offscreen target sized to the canvas backing store instead of the design size. Sprites sample nearest; imported HD sprites may sample linear. The camera can sit between pixels.
Lightnew
A second target at half resolution: an ambient colour plus additive point and cone lights drawn as soft sprites, multiplied over the scene. A lantern brightens the ground around it and the rest of the night stays dark.
Bloomchanged
A bright pass into a three-level mip chain with blur at each level, capped at a quarter of the target so phones pay a fixed price. Wide soft glow at 1440p instead of a single blurred thumbnail.
Gradenew
Saturation, contrast, tint and vignette as today, plus a colour lookup table for the scene's mood, film grain, and an optional scanline mask.
Textnew
A glyph cache rendered by Canvas 2D at device resolution for any web font and size, uploaded as a second texture and batched like sprites. The bitmap font stays for retro projects.
Presentchanged
A straight copy when the target is native; the integer upscale path remains for projects that choose it.

API sketch

Enough to check the shape. Everything here is additive; 0.1 projects keep running unchanged.

// blackiron.json
{
  "viewport": { "width": 1280, "height": 720, "scale": "fit" },
  "render":   { "scale": "native", "snap": "world" },
  "post":     { "bloom": 0.8, "lut": "dusk", "grain": 0.05, "vignette": 0.4 }
}
// Light: the lantern lights the ground, the night is dark elsewhere
const lights = this.world.add(new LightLayer({ ambient: 0x1a1f3a }));
const lantern = lights.add(new Light2D({ radius: 140, color: 0xffb060, flicker: 0.08 }));
lantern.follow(hero);

// HD text from any web font; the bitmap font is still there as { font: "pixel" }
new Label("EMBERS 12", x, y, { font: { family: "Bricolage Grotesque", size: 22, weight: 700 }, shadow: 0x000000 });

// Imported art packs into the same atlas as painted art
const sheet = await loadSheet("art/hero.json");   // Aseprite export: frames become sprites and animations

// Tiles with autotiling and collision built in
const map = new TileMap({ data: level, tileSize: 32, autotile: { ground: GROUND_SET } });
const r = map.moveBody(player, dx, dy);      // replaces the platformer's hand-rolled glue

// Overlay scenes draw over the one below and pause it
app.scenes.push(new PauseMenu(), { overlay: true });

// Painter 2.0: materials instead of pixel-by-pixel
p.material("bark", { x: 26, y: 44, w: 12, h: 46, ramp: trunk, seed: rng });
p.foliage(32, 30, 27, 22, leaf, { clumps: 6, light: [-0.4, -0.8] });

Definition of done

  • New projects default to 1280×720, native render scale and 32 px art; the demo and all starters are re-authored to match.
  • Every HUD and menu in the demo and starters uses HD text, and lays out correctly at 4:3, 16:9 and 21:9.
  • The demo's lantern and wisps light the world through the light pass, not through additive sprites alone.
  • One starter loads a PNG sprite sheet and a sound sample; painted and imported art share one atlas.
  • The platformer's collision and the top-down world run on TileMap; the platformer uses autotiling.
  • Every starter is playable with a gamepad and with touch controls.
  • Integer scaling, the bitmap font and 16 px art still work, covered by one retro variant of the blank starter.
  • Tests cover autotiling, layout, the glyph cache's measurement and the light layer's maths; total suite stays green.

Decisions

Each needs a yes before M0. A recommendation is given for all of them.

Default render scale

Native, with world snapping

Compose at the backing store's size. Sprites snap to art pixels in the world so they never shimmer; UI and particles move freely. Integer mode stays for retro projects.

AlternativeKeep design-size rendering and only raise art density. Cheaper, but glow and motion stay quantised.
Art density

32 px tiles on 1280×720

Forty by twenty-two tiles on screen, the same field of view as today with four times the detail. Characters at 32×48, big props up to 64×96.

Alternative48 px tiles. Prettier, but nine times today's painting cost per sprite and a 4096 atlas from day one.
HD text

Canvas 2D glyph cache

Render glyphs with the browser's text engine at device resolution into a texture, then batch them like sprites. Any web font, any size, one afternoon of code.

AlternativeSigned-distance fonts. Scale better under zoom, need a generator step per font. Revisit if text is zoomed in-world.
Lighting

A multiplied light map

Ambient plus soft additive lights in a half-resolution target, multiplied over the scene. Dramatic for night scenes and cheap on phones.

AlternativeNormal-mapped sprites. Real relief, but doubles the art work for every sprite.
Canvas 2D backend

Compatibility only

It keeps sprites, text, tint and the simple post chain so a game still runs without WebGL2. Lighting and grading are WebGL2 features and the docs say so.

AlternativeFull parity. Weeks of work for a fallback almost nobody sees.
Imported art

Same atlas as painted art

Sheets are unpacked at boot and packed next to painted sprites, so the batch stays one texture. The atlas grows to 2048 then 4096 before a second page is ever needed.

AlternativeSeparate textures per sheet. Simpler loader, more draw calls and a batching rewrite.

After 0.2

  • 0.3 Shells. Capacitor for iOS and Android with safe areas, prebaked atlases and IndexedDB saves; Tauri for desktop; the frame-time gate on real devices. Touch controls from 0.2 make this mostly packaging.
  • 0.4 Tooling. A scene inspector overlay, hot reload for painters, input record-and-replay, and screenshot parity in CI.
  • Later. Normal-mapped lighting, atlas pages, Tiled import, a second scripting surface if a non-programmer ever needs one.

Next step. Settle the six decisions. M0 starts by sizing the render target to the backing store, which is a one-day change, and the difference is visible in the gallery the same day.
