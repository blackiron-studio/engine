# Kiln roadmap: closing the gap with Godot and Unity

Written 2026-09-03 after 0.6. Kiln's runtime is close to what those engines give a 2D
game: a scene tree, native-resolution rendering with lights and post, sound, input,
saves, and native exports for web, iOS, Android, macOS, Windows and Linux. What is
missing is mostly around the runtime: the editor, physics, the animation and UI
systems, and the store and release plumbing. This is the order to close it in.

## Where Kiln stands

| Area | Godot / Unity | Kiln 0.6 |
|---|---|---|
| Scene tree, sprites, tiles, particles, lights, post | yes | yes |
| Exports | web, mobile, desktop, consoles | web, iOS, Android, macOS, Windows, Linux |
| Editor | full | none (code-first, dev server, debug overlay) |
| Physics | rigid bodies, shapes, joints, areas | tiles and overlap only |
| Animation | keyframe player, state machines | tweens, sprite animations |
| UI | full control set, themes, text input | labels, panels, buttons, bars, anchors, rows, columns |
| Scripting | GDScript, C#; debugger, profiler | TypeScript; source maps on the web only |
| Store and release | IAP, achievements, signing, Steam | icons and bundles; signing left to Xcode |
| 3D | yes | no, by design |

## Phase 1: data-driven scenes and an editor for levels (dropped)

Decided against on 2026-09-03: games are generated, not edited by hand, so the editor
brings nothing. A scene file format may still come with the kernel's retained scene.

- A scene file format: JSON describing nodes, properties and tile data, loaded with
  `Scene.fromFile`. Scenes stay classes for logic; the layout moves into data.
- A web editor served by `kiln dev`: tile painting with autotiles, placing sprites and
  nodes, an inspector for properties, a live link to the running game so edits show
  immediately and the game can be paused and stepped.
- Hot reload of scenes and art without losing game state.
- LDtk and Tiled import for people who already have levels.

## Phase 2: physics, animation, UI (done in 0.7)

- Physics in the kernel through rapier2d: bodies, shapes, joints, sensors, raycasts,
  collision layers, `moveAndSlide` for characters. Deterministic and identical on every
  platform, like the rest of the kernel.
- An AnimationPlayer: keyframe tracks on any property, sprite frames and sound
  triggers, blending, and a small state machine for characters.
- UI: text input, scroll containers, rich text with colours and icons, grids, tooltips,
  themes as style sheets, and screen transitions.
- Audio: OGG and MP3 samples in the generic host, positional audio, music crossfades.

## Phase 3: the kernel owns the scene, tooling matures (done in 0.8)

- A retained node table in the kernel so thousands of moving sprites cost nothing in
  script, then rendering inside the kernel with wgpu so every host is a thin shell,
  the Swift one included.
- V8 for desktop and Android, where a JIT is allowed, for script-heavy games; QuickJS
  stays the small fallback. JavaScriptCore's inspector on iOS for a real debugger.
- A profiler overlay per node and per system; a visual test harness that runs every
  project headless on each host and compares against golden images; Windows and Linux
  builds in CI with release artifacts.

Delivered in 0.8: SpritePool node tables, the wgpu renderer inside the kernel for every
native host, V8 on desktops behind an engine-neutral binding, the profiler, `kiln verify`
with goldens on desktop, iOS and Android, and the CI workflow. Not delivered: V8 on
Android (no prebuilt library), a kernel-side node hierarchy.

## Isometric and 2.5D worlds (0.9, milestones 1 to 3 done)

Height on nodes, projections (isometric, three-quarter tilt, top-down) with depth-sorted
passes in the kernel, isometric tile maps with elevation and fog tints, blob shadows, pools
with height, picking at a height, the Highground starter. See
`docs/proposals/0.9-isometric.html`. Still open from the proposal: 90° camera steps with
directional sprites, a per-tile sort origin in map definitions, goldens on iOS and Android
for the starter, and the sprite baker from 3D models.

## The shell (0.10, done)

Menus, settings, save slots and hints as optional modules (`@kiln/engine/shell`), wired
into Highground: title, pause with live settings and control rebinding, autosave and
Continue, one-time hints in the player's device's glyphs. Accessibility (shake, reduced
motion, text scale) and audio ducking came with it.

## The art pipeline (0.11, milestones 1 and 2 done)

Generic import, animation and rigs, so the engine gives a generator what Godot and Unity
give an artist: sprite-set manifests with facings, frame events and hitboxes; cutout rigs
from parts sheets over shipped templates with a procedural clip library; tileset import with
seam checks; a style linter with pitch and cast height; briefs the engine prints for the
image model; animation strips as goldens; export back to Aseprite. Twelve days across five
milestones. See `docs/proposals/0.11-art-pipeline.html`. Done so far: sprite sets with
facings, events, holds and hitboxes; `Rig2D` with four templates, nine procedural clips,
keyframed clips and layers; `kiln art parts`, `check` and `brief`. The knight runs as a sheet
and as a rig in `examples/knight` and is Wisp Hollow's hero as a rig. Next: tileset import
with seam checks (milestone 3), then strips as goldens and Aseprite export.

## Parity pass (0.12, done)

After the rig work the user asked for the rest of the gap to Godot and Unity for 2D, store
plumbing and Windows aside: normal-mapped procedural lights with occluder shadows, per-draw
materials, bus audio effects, shape casts and one-way platforms, blob autotiles with a tileset
importer, A* and tile colliders, rig blending and IK plus skinned meshes, localization, screen
reader announcements, input-method composition, and container widgets. Streaming music followed in 0.12.1. Still open: custom shaders (materials cover the common cases), skinned
meshes as an importable format, Windows and Linux builds from CI, store plumbing.

## Phase 4 (0.9 to 1.0): shipping

- Store plumbing: in-app purchases, achievements and leaderboards through Game Center
  and Play Games, Steam for desktop, cloud saves.
- Release packaging: iOS archives and signing, Android release keystores, macOS
  notarisation, Windows installers, one `kiln release` command.
- Documentation site with an API reference, guides, and more starters.

## Loose ends from 0.7 (closed in 0.7.1)

Android re-verified with physics, stereo audio and clipping; controllers and haptics on
Android through the generated KilnActivity; Row and Column place children by layout box;
tests for transitions and the phone text path.

## Deliberately later or never

- 3D. It is a separate multi-month track that changes the renderer, the scene tree and
  the editor. 2.5D effects (sprite stacking, parallax, lights) fit the current design.
- A general-purpose editor. The level and scene editor covers most of what a 2D game
  needs; an editor for everything is what makes Unity heavy.
- Networking beyond a transport and a lockstep helper, until a game needs it.
